# 资源选择规则详解

笔记末尾的资源链接怎么选、怎么摆、怎么写。

## 一、结构分两区

- `## 参考资源`（前面）：用于快速回忆，**2~4 条**
- `## 实操建议`（最后）：视频 / 链接 / 资源，**0~3 条**（各最多一条），宁缺毋滥，不为凑数

## 二、参考资源的 4 个层次（条数 = 覆盖必要层次的最少条数）

| 层次 | 定位 | 例子 |
|------|------|------|
| ① 直觉 | 短视频（≤10 分钟） | B站教程 |
| ② 快速权威 | 中文文章 / 经典 | 优质博客、官方中文文档 |
| ③ 系统 | 中文教材（书） | 《动手学深度学习》 |
| ④ 深度权威 | 英文文档（最权威，可占推荐位，标注「英文」） | 官方手册、原论文 |

> 优先推荐中文教材（方便阅读），再补充英文权威手册（深入学习）。

## 三、引用格式（禁止只丢裸链接，每条必须含）

1. **书籍**：`《书名》- 作者名 - 第 X 章（章节名）`
2. **芯片手册**：`芯片型号 + 文档编号 + 章节`
3. **应用笔记**：`厂商 + ANxxxx + 标题`
4. **在线资源**：`文章标题 + 作者/机构 + 链接`（作为补充，不替代书籍）

## 四、搜索原则（最高原则）

- **客观搜索**，忠于笔记主题思想，以「解决问题 + 提高认知 + 沉淀知识」为唯一目的；
- **不预设**对任何来源的偏好或偏见，以内容质量和权威性为判断标准；
- **优先权威免费来源**：官方文档、中文教材、大学 MOOC、开源社区文档等免费且权威的来源；谨慎引用收费内容，避免读者打开付费墙造成不良体验；
- 广泛搜索，不局限固定网站（优先用已有的搜索 skill、WebSearch）。

## 五、格式约束

- 不用「必读/必看/必记」等主观夸大词；
- 视频条目不写「长视频/短视频」等泛化词，写具体时长（如「3分45秒」）；
- 英文标注以「打开网站后用户看到中文还是英文」为准（中文转载不标英文，英文原文标「英文」）；
- 收费内容若引用：保留原链接并明确标注收费属性，同时提供免费替代来源（网站不限）。

## 六、特例（学习计划/路线类笔记）

制定学习计划时免不了按学习路径引用大量学习资源和实操建议，此时**打破** `参考资源 2~4 条 + 实操建议 0~3 条` 的条数限制——按学习路径附上足够多的资源，**资源链接没有上限**。

## 七、实操建议示例

每条实操建议应是「可执行的动作」，而非「泛泛的鼓励」。例如：

- ✅ 好：「先看 B 站视频建立整体印象，再逐词啃 6 个概念，最后用自检问题验证——答不出来就回看池化/上采样两条。」
- ❌ 差：「多加练习」「注意理解」

## 八、权威中文来源参考

选择资源时，优先考虑以下免费、权威、中文友好的来源：

### 官方中文文档

- [MDN Web Docs 中文版](https://developer.mozilla.org/zh-CN/) — Web 技术的权威中文参考；
- 各技术的官方中文文档，如 [ESP-IDF 官方中文文档](https://docs.espressif.com/projects/esp-idf/zh_CN/latest/)、Python、React、Vue 等。

### 中文教材（免费）

- [《动手学深度学习》中文版（d2l.ai）](https://zh.d2l.ai/) — 深度学习领域权威中文教材；
- [廖雪峰的官方网站](https://liaoxuefeng.com/) — Python 等编程语言的免费系统教程。

### 大学 MOOC

- [中国大学 MOOC](https://www.icourse163.org/) — 高校精品课程的免费平台。

### 开源社区文档

- GitHub 上各开源项目的官方文档（多数提供中文版本）。

> 原则：来源的「权威性」与「免费性」优先于「平台名气」。同一知识点若有官方中文文档或免费教材，优先采用，而非收费的第三方内容。
