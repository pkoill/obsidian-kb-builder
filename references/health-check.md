# 健康检查流程

健康检查的详细执行流程。定期检查知识库是否健康，及时清理冗余、修复断链。

## 检查清单（按优先级）

### 1. 断链检查（最高优先级）

wikilink 指向不存在的笔记 = 断链，是知识库最常见的损坏。

```bash
obsidian unresolved verbose
```

- 结果应为空；若有断链，逐个修复：要么补建目标笔记，要么修正 `[[链接名]]`。
- **触发时机**：任何改名、移动、批量替换笔记后，必须执行一次。

### 2. 孤儿文件检查

```bash
obsidian orphans
```

孤儿 = 无任何笔记链接到它。**正常的孤儿**：首页、模板、附件、README、交接文档（本就该是入口，不该被链接）。**异常的孤儿**：本该被其他笔记引用的主题笔记/学习笔记，说明知识碎片化或漏了链接。

### 3. 重复待办检查

```bash
obsidian tasks todo verbose
```

比对同一待办描述是否在多个文件重复出现。若重复：

1. 判断保留哪一处语义最合适（如「联系导师」放周复盘「下周重点」比放某篇学习笔记「待跟进」更合理）；
2. 删除其余，保留一处。

### 4. 空 checkbox 检查

模板文件里的空 `- [ ]` 占位符会被 Dataview 的 `TASK` 查询当成空任务抓进首页。

```bash
grep -rn "^-\s*\[ \]\s*$" --include="*.md" <vault路径>
```

处理：删除空 checkbox，用 HTML 注释（`<!-- 提示 -->`）保留「这里该填什么」的说明——注释不渲染、也不被 Dataview 抓取。

### 5. status 准确性抽查

抽查近期笔记的 frontmatter `status` 是否如实：

- 内容完整但还标 `seed（种子）` → 升 `sapling（树苗）`；
- 反复修订稳定的 `sapling` → 升 `evergreen（常青）`；
- 零散草稿误标 `sapling` → 降 `seed`。

### 6. 过时 / 归档检查

- `1-收纳/2-项目/` 中超过 60 天无活动的项目，建议标记归档；
- `1-收纳/1-收件箱/` 中久未分类的条目，提示用户处理。

## 输出报告

检查完成后，输出一份结构化报告：

```
## 知识库健康报告

- 断链：N 处（已修复/待修复清单）
- 孤儿文件：N 个（正常 N 个 + 异常 N 个）
- 重复待办：N 组（处理结果）
- 空 checkbox：N 处（已清理）
- status 偏差：N 处（已调整）
- 待归档项目：N 个

### 建议操作
（按优先级列出需要用户确认的操作）
```

> 修复动作分两类：**无风险自动修复**（删空 checkbox、合并明显重复待办）可直接做；**涉及内容判断**（断链指向哪篇、孤儿该不该链接）需列给用户确认后再动。
