# Obsidian 个人知识库构建

教 Claude Code 从零构建和维护一个**个人 Obsidian 知识库**——记录学习、沉淀知识、每周复盘，让下次遇到同类问题能快速解决的系统化方法。本 Skill 的参考实现是一套经过实际使用验证的架构（学习笔记/主题笔记二分 + 收纳区 + 序号命名）。

## 核心原则

1. **笔记二分**：学习笔记记「这次的事件」（时间、场景、踩坑、解决步骤）；主题笔记记「通用的概念」（定义→原理→应用，脱离当前项目仍成立）。判断标准：换到下一个项目，这个知识还会回来查吗？会 → 主题笔记；不会 → 留在学习笔记。
2. **新建 vs 并入（硬规则）**：写任何新笔记前先搜索知识库。已有同主题 → 更新现有笔记（补章节、改参数、加修订）；没有 → 才新建。同一主题只允许存在一篇，宁可丰富一篇笔记，不分散创建多篇浅薄笔记。
3. **status 三级流转**：`seed（种子）` → `sapling（树苗）` → `evergreen（常青）`。新建即定级：内容完整填 `sapling`，零散草稿填 `seed`；更新笔记时顺手升级。
4. **链接必填，拒绝空白**：写 `[[wikilink]]` 时必须一并创建对应笔记并填入内容，禁止空占位链接。
5. **随时打通链接**：学习用户原有笔记时，为笔记之间补上链接；写新笔记时主动引用相关旧笔记；写完检查「这篇引用了谁、被谁引用」，实现笔记之间的跳转。**关键：学习笔记正文中第一次提到某个已有主题笔记的概念时，当场用 `[[wikilink]]` 链接到该主题笔记**（如「……涉及 [[反向传播]] 的链式法则……」），让读者点击即跳转。
6. **半自动**：整理和建议由 Claude 自动完成，但写入 vault 前经用户确认。

## 目录结构（默认，名字可自定义，若用户已经存在知识库，需先阅读当前知识库结构在决定下面结构有那些是需要构建的，禁止删除用户原有知识库结构）
学习用户原有笔记，为用户笔记之间加上链接，实现笔记之间的跳转


该结构在用户提供的知识库中不存在时，Claude 会自动创建全部完成。（按 skill 的目录结构搭建好，笔记间跳转全部打通）；若用户已有知识库，Claude 会先分析现有结构，对照下方结构逐项判断——用户已有且功能对应的目录保留原名、不重建；本文档有而用户缺失的目录才按需补建（只建后续会实际用到的，不空建），新建笔记时序号接续用户已有体系（学习笔记接着现有最大序号往后排，如已有 `1-`～`8-`，下一篇用 `9-`），不重排、不覆盖用户已有命名，禁止删除用户原有知识库结构。

当发现用户的知识库中含有笔记时，主动询问用户是否按照 Skill 中的目录搭建，同时把 Skill 中的目录告诉用户，或者建议建立一个新的知识库。

```
Vault/
├── 0-首页.md          ← 库的总入口（数字-名字）；Pinit 插件置顶，Homepage 插件自动加载
├── 1-收纳/            ← 收纳区
│   ├── 1-收件箱/      ← 快速捕获，待分类
│   ├── 2-项目/        ← 活跃项目
│   ├── 3-领域/        ← 持续责任领域
│   ├── 4-归档/        ← 已完成/暂停项目
│   ├── 5-个人档案/    ← 使用者个人档案（用户档案、导师、培养方案等；可选）
│   └── 附件/          ← 手册、图片等附件
├── 2-学习笔记/        ← 学习笔记（问题解决笔记，主角）
├── 3-主题笔记/        ← 主题笔记（通用知识，配角）
├── 4-周复盘/          ← 每周总结
├── 问题索引.md        ← 遇到问题先查这里
└── README.md          ← 库说明
```

> **存放规则（硬规则）**：学习笔记、计划笔记（学习计划/学习路线）、决策记录等内容，**统一存放 `2-学习笔记/`**，不另设项目目录，不放 `1-收纳/` 或 Vault 根目录；`3-主题笔记/` 只放通用知识主题笔记。

## 命名规范

| 对象 | 格式 | 例子 |
|------|------|------|
| 顶级目录 / 顶级文件 | `数字-名字`（连字符 `-`） | `0-首页`、`1-收纳`、`2-学习笔记` |
| 学习笔记 | `序号. 题目`（点 + 空格） | `1. 知识库搭建与学习启动.md` |
| 主题笔记 | `题目`（纯题目名，**严禁**时间戳） | `单片机GPIO原理.md` |
| 周复盘 | `W周数-日期` | `W33-2026-08-13.md` |

> **注意**：命名规则三易混点：
> - 顶级条目用**连字符**（`1-收纳`），学习笔记用**点+空格**（`1. 题目`），两者不可混用；
> - 主题笔记带时间戳（如 `2026-08-05_题目.md`）= wikilink 断裂，Obsidian 找不到会自建空白文件；
> - `[[wikilink]]` 按**文件名**全局匹配，与目录无关——命名错了，链接就断。

## 笔记结构

**学习笔记**（问题驱动，结尾栏目顺序固定）：

```
## 做了什么          ← 一句话说清这篇解决了什么问题
## 正文              ← 标题按问题自由起，每节按「定义 → 原理 → 应用」写
## ⏳ 待跟进          ← 未完成的待办，用 `- [ ]` 复选框列出（可勾选划掉）；没有就写「无」，保持栏目  
## 参考资源          ← 外部权威资源
## 实操建议          ← 资料链接（视频/中文资源/英文资源，1~3 条，每类最多 1 条）这一栏目必须要有
## 相关链接          ← 内部 wikilink
## 💡 随手记          ← 零散想法，放最后
```

**计划类笔记**（学习路线/学习计划，打破上述结构，步骤驱动；层次感靠阶段分组 + 栏目顺序固定 + 标题具体化，详见 `references/writing.md`）：

## 📄 核心论文（可选）

计划涉及重要/经典论文时加此章节，用引用块呈现：`> **《论文标题》** —— 作者，机构，年份，会议。` 下一行写 `> arXiv: [编号](链接)（语言），全文 X 页。` 再写一句论文贡献；最后一句「学习路线围绕它展开」串联各步骤。**触发条件**：用户是研究生/科研本科生必带；未透露身份但涉及重要论文或前沿方向也带；详见 `references/writing.md`。

> **时间安排（按需）**：做计划先问用户「基础水平 + 计划周期（多少周完成，不问每天几小时）」，周期选项给 3 个——前两个是 Agent 推荐的时长、第 3 个「不设定确切时间」；选了具体周数才用本地当前时间推算日期，选「不设定确切时间」则不写具体日期。

① <第 1 步主题>（<时间>）── <关键内容> 
  │
  ▼
② <第 2 步主题>（<时间>）── <关键内容> 


### 第 1 步：<具体动作主题>（<时间/天数>）

- [ ] 具体任务2 📅 到期日

> 每个 `- [ ]` 任务都必须带 `📅 到期日`，不能只给第一条标日期。

**学习资源**（每条步骤至少 4 条，一条一行）：

- [视频标题](链接) — 说明，第一条必须是视频，链接文本写该视频标题，并控制时长（直觉 10 分钟左右、深刻理解 1 小时内）；若引用合集须标出「第 N 集」并让链接直达该集
- [标题](链接) — 说明，后续链接：中文资源网站/中文资源视频/官方中文文档/官方英文文档
- [标题](链接) — 说明
- [标题](链接) — 说明
- [标题](链接) — 说明
......

**实操建议**：文字建议，实操建议必须要有，计划类笔记的实操建议是「具体怎么做」的文字，不是资源链接。

结尾以 `## 相关链接` 收尾，不加「关键里程碑」等总结栏目；frontmatter 含 `created`（创建时间）+ `start_date`（开始时间）+ `end_date`（结束时间），`status` 用计划标签（`active（进行中）`/`paused（暂停）`/`completed（已完成）`/`abandoned（废弃）`），不用 seed/sapling/evergreen。

## Frontmatter 规范

- 学习笔记：`created`（创建时间）+ `start_date`（开始时间）+ `end_date`（结束时间）+ `tags` + `status`
- 主题笔记：`created`（创建时间）+ `tags` + `status`
- 计划类笔记：`created`（创建时间）+ `start_date`（开始时间）+ `end_date`（结束时间）+ `tags` + `status`（计划标签）
- 时间字段统一 `YYYY-MM-DD` 格式（如 `2026-08-15`）
- 标签判断标准「大众熟知」：缩写、型号、工具名用英文（`STM32`、`GPIO`、`I2C`、`Python`、`MySQL`、`Git`、`CNN`等等），描述词用中文（`嵌入式`、`时钟`、`算法`、`网络`、`数据库`、`缓存`等）；英文缩写与中文概念可并存（`RCC` + `时钟`、`CNN` + `卷积`、`Redis` + `缓存`等）
- 章节用 `##`/`###`，表格对比、代码块示例、引用块提示（详见 `references/writing.md`）

## 写作原则

1. **结构：定义 → 原理 → 应用**——定义一句话，原理讲清「为什么」，应用给可直接参考的例子。
2. **类比先行，细节收束**——抽象概念先用日常事物建立直觉（一两句），随即回到真实的技术细节。
3. **简洁，但不省略关键参数**——技术参数给具体数值（「~20mA」而非「较大电流」）；首次出现的术语要解释。
4. **严谨克制**——避免「显而易见/众所周知」等词；关键警告用 `> **注意**：`，常见错误用 `> 常见错误：` 并附排查方法。
5. **主题笔记额外要求**——写主题笔记时：联网搜索按「分层触发」（具体数值/参数/版本/最新进展/资源链接必搜，稳定基础概念可基于已有知识）；开头加「前置知识」声明；详见 `references/writing.md`。
6. **代码块先交代目的**——写代码块前用一句话说明「这是 XX 代码、作用是 XX」，让读者带着目的读；不逐行解释。
7. **文风前后一致**——整篇笔记保持统一文风，不突然从严肃变活泼或反之。
8. **禁止预设基础**——写任何内容都不预设读者已有相关基础，把读者当作首次接触来写：遇到的术语、概念、方法都要解释，不默认读者「应该已经会了」。
9. **善用引用块增加层次感**——多用 `>` 引用块（Obsidian 里显示为左侧带主题色竖线）突出关键提示（注意 / 常见错误 / 前置知识 / 总结等），让笔记有层次感。

写完自检（三层均合格方视为通过）：核心层（定义/结论精确到能直接引用）→ 机理层（讲清因果链）→ 参考层（给了具体数值/边界）。

## 资源规则

笔记末尾的资源分两区（详见 `references/resources.md`）：

- `## 参考资源`（2~3 条，4 层次：① 短视频直觉 → ② 中文资源（博客、网站等）→ ③ 中文教材 → ④ 英文文档权威）
- `## 实操建议`（学习笔记/主题笔记放资料链接：视频/中文资源/英文资源 1~3 条、每类最多 1 条；计划类笔记放「具体怎么做」的文字；）
- **特例**：学习计划/路线类笔记打破条数限制，每条步骤的学习资源**至少 4 条**、一条一行；第一条必须是视频（链接文本写视频标题，合集须标出具体集数）；同一主题只留质量最高的一个。

## 前置依赖

本 skill 依赖以下工具（**非本 skill 自带，不自动安装**）：

| 依赖 | 用途 | 必需性 |
|------|------|--------|
| [Obsidian CLI](https://obsidian.md/cli) | `obsidian search`/`backlinks`/`unresolved` 等 vault 操作 | 强烈推荐（Obsidian 1.12.7+，设置 → 选项 → 高级 → 命令行界面） |
| [kepano/obsidian-skills](https://github.com/kepano/obsidian-skills) | Obsidian 语法/Canvas/Bases 的细粒度 skill | 推荐（`/plugin marketplace add kepano/obsidian-skills`） |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | Agent 浏览器自动化，用于网页搜索与内容提取 | 推荐（搜索资源的可选增强，`npx @playwright/mcp@latest`） |

> 若运行时检测到缺少上述依赖，Agent 应先检查是否需要安装。
需要安装的obsidian插件：Dataview：把整个 vault 当数据库，用类 SQL 的查询语言动态生成表格/列表 在知识库里的作用： 首页按 status/tags 展示所有笔记的成熟度总览
Homepage：指定一篇笔记作为启动首页，打开 Obsidian 自动显示 在知识库里的作用： 一打开就进入 0-首页.md（上面就是 Dataview 面板）
Open Tab Settings：控制新标签页打开的位置和行为 在知识库里的作用：点 [[wikilink]] 跳转时，新笔记在「当前标签旁」打开，方便相邻笔记对照阅读
Tasks：用查询语法跨笔记搜集、筛选、汇总待办（checkbox）在知识库里的作用：把学习计划里的 - [ ] 任务 📅 到期日 汇总成「今日/逾期」面板
