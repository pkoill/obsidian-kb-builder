# 写作原则与笔记结构详解

## 一、学习笔记 vs 主题笔记（何时抽主题笔记）

两者都要求知识密度大，区别**不在详略，而在「通用 vs 私有」**；其中主题笔记作为通用知识的细致补充，**必须详尽充实、知识量足、把知识解释透**（按「定义 → 原理 → 应用 → 对比 → 参数」层层展开，让读者读这一篇就能彻底理解该主题，不必再查其他资料）：

| | 学习笔记 | 主题笔记 |
|---|---------|---------|
| 记什么 | 这次的事件（时间、场景、踩坑、解决步骤） | 通用的概念（定义→原理→应用→对比，脱离当前项目仍成立） |
| 判断标准 | 换到下一个项目，这个知识还会回来查吗？ | 会 → 抽主题笔记；不会 → 留在学习笔记 |

**触发抽主题笔记的四个信号**（命中任一即可）：

1. **第二次出现**：概念已在别的笔记提过、或预感还会再提，避免每篇重复解释；
2. **正文膨胀**：概念解释越写越长，盖过「问题解决」主线，需独立成篇；
3. **脱离场景仍成立**：换芯片/产品/项目/公司仍成立（GPIO 开漏推挽、I²C 时序、中断机制，IDE配置，产品说明等等），而非只对当前项目/产品/芯片/寄存器等等学习内容或主题有效；
4. **`[[概念]]` 是空的**：写 wikilink 时链接目标不存在对应主题笔记，即视为需补写的信号。

**不抽主题笔记的情况**：一次性的步骤/踩坑、三言两语即可说明的小技巧、绑定具体芯片型号或工程路径的配置。

操作流程：先搜知识库有无同主题（并入/新建规则见「新建 vs 并入」）；没有同主题时，再按上述判据决定抽主题笔记还是留在学习笔记。

**主题笔记撰写要求**（写主题笔记时，在「定义 → 原理 → 应用」之外额外遵守）：

1. **详细易懂 + 学术严肃**：用类比建立直觉、短句层层递进（易懂）；同时定义精确、结论给边界条件、术语首次出现即定义、引用权威来源（严肃）。自检：核心结论能直接引用，不含「大概」「似乎」。
2. **联网搜索（分层触发）**：以下内容**必须联网搜索**验证——具体数值/参数/性能指标、工具与框架的版本用法、最新进展与新模型（「当前 SOTA」类表述）、资源链接的真实性；稳定的基础概念定义、经典原理、数学公式可基于已有知识撰写，但须通过「写完自检」保证准确。
3. **面向计算机学生**：开头用一句话写「前置知识」声明（读这篇需要哪些基础，缺了先去补哪）；正文用 `> 常见错误：` 标注学生常踩的坑并附排查方法。

## 二、学习笔记正文结构

开头「做了什么」+ 主体按问题自由起 + 结尾栏目顺序固定：

```
## 做了什么（或 ## 问题背景）   ← 一句话说清这篇解决了什么问题
## 正文标题（自由起）           ← 每节按「定义 → 原理 → 应用」写
## 待跟进                    ← 未完成的待办，用 `- [ ]` 复选框列出（可勾选划掉）；没有就写「无」，保持栏目
## 参考资源                     ← 外部权威资源
## 实操建议                     ← 视频/链接/资源，1~3 条
## 相关链接                     ← 内部 wikilink
## 随手记                    ← 零散想法，放所有栏目的最后
```

知识密度要求：学习笔记是「遇到问题快速解决」的核心，不只是记「做了什么」，而是把涉及的概念、原理、机制**详尽展开**（定义→原理→对比→参数），让读者看这一篇就能解决问题，不必跳去别处。

**正文打链接（硬规则）**：正文中**第一次**提到某个已有主题笔记的概念时，当场用 `[[主题笔记名]]` 链接（如「……涉及 [[反向传播]] 的链式法则……」），让读者点击即跳转；不要等结尾「相关链接」才集中列出。

## 三、计划类笔记结构（步骤驱动）

学习路线、学习计划、学习规划类笔记，**打破**普通学习笔记「结尾才放参考资源+实操建议」的结构，改为步骤驱动。层次感靠三件事：**阶段分组、栏目顺序固定、标题具体化**。

- **学习地图**：计划开头必须有 `## 学习地图` 栏目，用 ASCII 流程图画出全部步骤骨架——每一步「`① 步骤名（时间）── 关键内容`」，用 `│` `▼` 纵向串联，让读者一眼看到整体路径；
- **阶段分组**：步骤超过 6 个时，用 `## 阶段N：主题（时间）`步骤少（≤6 个）可不分阶段，直接用 `###` 步骤；
- **栏目顺序固定**：每个步骤内部，任务、学习资源、实操建议 三个栏目的顺序永远一致，读者扫读形成肌肉记忆；
- **标题具体化**：步骤标题写「具体动作」，如「第 3 步：跑通 MNIST 手写识别」，**不要写成「第 N 步：学什么」这种占位**；
- 步骤内的具体任务用复选框 `- [ ]` 列出，**每条任务都必须带 `📅 到期日`**（不能只标第一条），完成即可勾选划掉，也会被首页 Dataview 的 `TASK` 查询抓取为待办；
- 每个步骤下**必须有学习资源链接**，**至少 4 条**、**一条一行**（`- [标题](链接) — 说明`）——刚开始学需要大量资源辅助理解，宁多勿少，不能只给两三个；**第一条必须是视频**，链接文本写该视频的**具体标题**，并**控制时长**（直觉定位 10 分钟左右，深刻理解定位最好 1 小时内，尽量短）；若引用的是视频合集（B 站系列、播放列表等），须标出具体第几集并让链接直达该集（如 B 站链接带 `?p=N`）；但**同一主题/内容只保留质量最高的一个**，多个链接讲同一件事时删掉冗余的；
- 必须要有实操建议（计划类笔记的实操建议是「具体怎么做」的文字，不是资源链接）
- 计划类笔记每条步骤的「学习资源」**至少 4 条**，不套用学习笔记/主题笔记「参考资源 2~3 条」的条数限制。
- **论文呈现（按需）**：计划涉及重要/经典论文（如 Transformer 的《Attention Is All You Need》）时，在 `## 学习地图` 之前加 `## 📄 核心论文` 章节，用引用块呈现论文。**触发条件**：① 用户明确是研究生或做科研的本科生 → 必带；② 用户未透露身份，但识别到计划涉及重要论文或前沿/热门方向 → 带；③ 其余不带。
- **时间安排（按需询问，不默认定时）**：做学习计划时，先询问用户两点——① **基础水平**（零基础 / 有部分基础 / 已有基础等）；② **可用学习时间**（如「每天 X 小时」「每周 X 天」）。询问学习时间时，选项里**必须包含「不设定确切时间」**。用户给了时间 → 用**本地当前时间**推算 `start_date` / `end_date` 和每步的 `📅 到期日`（不凭记忆硬编码日期）；用户选「不设定确切时间」→ 不写具体日期，`📅 到期日` 可省略或改用相对时间（如「第 1 周」）。

结构模板：

## 📄 核心论文（可选，涉及重要论文时才加）

<一句话说明论文与计划的关联，如「本计划的最终目标是读懂这篇开山之作：」>

> **《论文标题》** —— 作者，机构，年份，会议。
> arXiv: [编号](链接)（语言），全文 X 页。
> 一句话说明论文的地位/贡献。

学习路线围绕它展开：<简述各步骤如何对应论文>。

## 学习地图
采用如下结构，使用ASCII 流程图画出全部步骤骨架——每一步「`① 步骤名（时间）── 关键内容  」，用 `│` `▼` 纵向串联，让读者一眼看到整体路径。
① <第 1 步主题>（<时间>）── <关键内容>
  │
  ▼
② <第 2 步主题>（<时间>）── <关键内容>

### 第 1 步：<具体动作主题>（<时间/天数>）

- [ ] 具体任务1 📅 到期日
- [ ] 具体任务2 📅 到期日

**学习资源**（每条步骤至少 4 条，一条一行）：

- [视频标题](链接) — 说明，第一条必须是视频，链接文本写该视频标题，并控制时长（直觉 10 分钟左右、深刻理解 1 小时内）；若引用合集须标出「第 N 集」并让链接直达该集
- [标题](链接) — 说明，后续链接：中文资源网站/中文资源视频/官方中文文档/官方英文文档
- [标题](链接) — 说明
- [标题](链接) — 说明
- [标题](链接) — 说明
......

**实操建议**：实操建议必须要有，这一步「具体怎么做」的文字（可执行动作，不是资源链接）

笔记整体结构：开头 `## 做了什么`（一句话 + 计划目标/背景）→ `## 学习地图`（整体路线一览）→ 中间按阶段/步骤模板写 → 结尾 `## 相关链接`。**不加「关键里程碑」等总结栏目**——整体节奏已在路线图/步骤时间中体现，重复汇总属于冗余。

计划类笔记的 frontmatter 含 `created`（创建时间）+ `start_date`（开始时间）+ `end_date`（结束时间），`status` 不用 seed/sapling/evergreen，改用计划专用标签：

| status | 含义 | 何时到达 |
|--------|------|---------|
| `active（进行中）` | 正在按计划推进 | 开始执行后 |
| `completed（已完成）` | 全部步骤完成 | 计划全部完成 |
| `abandoned（废弃）` | 终止，不再继续 | 决定废弃计划时 |

**目标读者**：计算机大类在校学生。笔记应具备大学工科教材的严谨性，表述清晰、逻辑严密、层层递进。判断标准：一名大学工科首次接触该概念的用户，能否通过阅读建立正确理解。

## 四、写作风格八条规则

1. **结构：定义 → 原理 → 应用**
 - 定义：一句话给出精确定义
 - 原理：为什么需要它？解决了什么问题？核心工作机制是什么？
 - 应用：具体的电路或代码示例，读者可直接参考

2. **类比先行，细节收束**
 - 对抽象概念，优先用日常事物建立直观理解
 - 例："推挽输出——电路能主动驱动 HIGH 和 LOW，类似双手推拉"
 - 例："开漏输出——只能主动拉 LOW，拉 HIGH 依赖外部上拉电阻，类似单向阀门"
 - 类比一句话、最多两句，随即回到真实的电路结构、寄存器、波形等技术细节

3. **简洁，但不省略关键参数**
 - 句子宜短不宜长，一句表达一个要点
 - 技术参数必须给出具体数值（如 "~20mA" 而非 "较大电流"）
 - 首次出现的术语需要解释，不预设读者已有知识
 - 优先用 ASCII 图示替代冗长文字

4. **严谨克制，避免主观语气**
 - 禁止"显而易见""显然""众所周知"等词汇
 - 避免"你会发现""你会注意到"等主观引导句式；用客观陈述替代（不说"这里要注意"，直接写"限制条件：……"）
 - 关键警告用 `> **注意**：` 标注，常见错误用 `> 常见错误：` 标注并附排查方法

5. **代码块先交代目的**
 - 写代码块前，先用一句话说明「这是 XX（语言）代码，作用是 XX」，让读者带着目的进入代码、不至于懵
 - 不要求逐行解释每一行含义（那是注释和教材的职责）
 - 例：`下面这段 Python 代码，演示 PyTorch 的 autograd 如何自动计算梯度：`

6. **文风前后一致**
 - 整篇笔记保持统一的文风，不突然变得严肃或活泼
 - 一旦定下基调（严谨、通俗、类比式等），通篇贯彻，不中途切换

7. **禁止预设基础**
 - 写任何内容都不预设读者已有相关基础，把读者当作首次接触该概念来写
 - 遇到的术语、概念、方法都要解释，不默认读者「应该已经会了」

8. **善用引用块，增加层次感**
 - 写笔记时多用引用块 `>`——它在 Obsidian 里渲染为左侧带一条竖线的块，竖线颜色跟随当前主题，天然起到分隔与强调作用
 - 用引用块把关键内容从正文中「拎出来」：`> **注意**：`、`> **常见错误**：`、`> **前置知识**：`、`> **总结**：` 等
 - 长正文段落之间穿插引用块打破单调，但不要滥用——引用块过多会稀释强调效果


## 五、内容五层骨架

| 层级 | 内容 | 目的 |
|------|------|------|
| 直觉层 | 类比、场景、问题引入 | 建立直观理解，降低认知门槛 |
| 原理层 | 结构、时序、机制 | 建立系统性的工程理解 |
| 实战层 | 代码、示例、参数计算 | 提供可直接参考的实现 |
| 对比层 | 不同方案对比、选型决策 | 培养工程判断能力 |
| 参考层 | 权威书籍、手册、官方文档 | 提供深入学习路径 |

## 六、写完自检（按三层信息密度检查，三层都合格才算过关）

1. **核心层**：定义、结论、边界条件是否精确到能直接引用？不含「大概」「似乎」。
2. **机理层**：是否讲清了「为什么这样工作」的因果链？
3. **参考层**：是否给了具体数值/边界？（「~20mA」而非「较大电流」）

## 七、Frontmatter 规范

- 学习笔记：`created`（创建时间）+ `start_date`（开始时间）+ `end_date`（结束时间）+ `tags` + `status`
- 主题笔记：`created`（创建时间）+ `tags` + `status`
- 计划类笔记：`created`（创建时间）+ `start_date`（开始时间）+ `end_date`（结束时间）+ `tags` + `status`（计划标签）
- 时间字段统一 `YYYY-MM-DD` 格式
- 标签判断标准「大众熟知」：缩写、型号、工具名用英文（`STM32`、`GPIO`、`I2C`、`RCC`、`SysTick`、`UART`、`Python`、`MySQL`、`Git`、`HTTP`、`CNN` 等等相关领域名词），描述词用中文（`嵌入式`、`时钟`、`定时器`、`串口`、`算法`、`网络`、`数据库`、`缓存`、`并发` 等等相关领域名词）；英文缩写与中文概念可并存（`RCC` + `时钟`、`CNN` + `卷积`、`Redis` + `缓存`、`TCP` + `网络`）
- 章节用 `##` 二级标题、`###` 三级标题；表格用于对比、代码块用于示例、引用块用于提示

## 八、status 三级流转

> **注意**：本三级仅适用于学习笔记与主题笔记；计划类笔记改用计划专用标签（见「三、计划类笔记结构」）。

| status | 含义 | 何时到达 |
|--------|------|---------|
| `seed（种子）` | 刚记下，零散、未结构化 | 零散草稿、临时记录 |
| `sapling（树苗）` | 已整理，具备「定义→原理→应用」结构 | 内容写完整后 |
| `evergreen（常青）` | 反复修订成熟，可长期引用 | 多次修订稳定后 |

- 值写成「英文 + 中文注释」形式。
- 由 Claude 在「写/改笔记时」顺手定级：新建即定级（完整填 `sapling`，草稿填 `seed`），更新/并入时顺手升级。

## 九、过时/被推翻笔记的处理

- 认知被推翻 → **在原笔记改正文**，可加「修订记录」一节，**不堆 `_v2`**；
- 只有「两种观点并存、需要对比」时才保留两个版本；
- 历史留痕交给文件恢复 / git，不靠堆文件。
